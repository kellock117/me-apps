# 할 일 알림은 저장하지 않고 계산하고, "읽음"만 저장한다

독서 앱의 할 일 알림(🔔·할 일 모달: 별점, 이번 주 진도)은 알림 표에 쌓지 않는다. 볼 때마다 책·모임·평점·진도에서 `pendingNotices`로 계산하고, 멤버가 숨긴 알림의 키만 `book_notice_dismissals`에 저장한다(스펙 #45, #50·#51). 알림이 전부 이미 있는 데이터에서 나오는 "상태"라서, 따로 저장하면 원본과 어긋날 수 있다. 원본과 어긋나지 않게 하려면 주차가 열릴 때 만들고 평점·진도를 적으면 지우는 크론이나 트리거가 필요한데, 계산하면 그런 장치 없이 항상 맞는다.

## Considered Options

- **알림 표에 저장(행마다 읽음 여부)**: 주차가 열리는 날 알림을 만들 크론과, 평점·진도 저장 때 알림을 지우는 처리가 필요하다. 하나라도 빠지면 이미 한 일이 알림으로 남거나 할 일이 알림에 안 뜬다. 멤버 4명 규모라 저장으로 아낄 계산도 없다.
- **읽음을 `localStorage`에만**: 표가 필요 없지만 기기마다 따로라서 휴대폰에서 숨긴 알림이 컴퓨터에서 다시 보인다. 할 일 모달의 "하루 한 번"은 이 방식을 쓰지만(가벼운 표시라 기기별이어도 괜찮다), 숨김은 멤버 단위여야 한다.

## Consequences

- 알림 키에 숨김의 범위를 담는다. 진도는 `progress:<책>:<주차>`라 다음 주차가 열리면 새 키로 다시 나온다. 키 모양을 바꾸면 옛 숨김 기록이 맞지 않게 되므로 함께 옮겨야 한다.
- 평점 알림(`rate:<책>`)은 숨길 수 없다. 별점을 매겨야만 사라진다. 서버 액션(zod)과 DB check 제약이 진도 키만 받는다.
- 지난 주차의 숨김 기록은 지우지 않고 쌓인다. 작은 표라 그대로 둔다.
- 웹 푸시(TODO `reading-push`)를 붙일 때도 보낼 대상은 같은 계산으로 구하고, "보낸 기록"이 필요하면 숨김처럼 따로 저장한다.
