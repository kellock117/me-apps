# 네이티브 앱 대신 PWA와 웹 푸시로 알림을 보낸다

독서 앱의 진도·모임 알림(스펙 #53)은 iOS·Android 앱을 새로 만들지 않고, 지금의 웹 앱을 PWA로 설치하게 하고 웹 푸시(Push API, VAPID)로 보낸다. 사용자는 멤버 몇 명이고 기기는 대부분 iPhone이라, 앱 스토어 배포와 두 번째 코드베이스를 감당할 이유가 없다. iPhone은 iOS 16.4 이상에서 **홈 화면에 추가한 앱**에서만 웹 푸시를 받을 수 있어서, 멤버가 한 번 "홈 화면에 추가"를 해야 한다는 부담은 받아들인다.

## Considered Options

- **네이티브 앱(Swift 등)**: 푸시가 가장 안정적이다. 하지만 Apple Developer 가입이 연 $99이고, 서버 쪽 APNs 연동과 앱 코드를 새로 만들어야 한다. 앱 스토어 심사를 피하려고 TestFlight로 돌리면 빌드가 90일마다 만료되어 다시 올려야 한다. 이 앱의 화면은 전부 웹에 이미 있다.
- **크로스 플랫폼(React Native, Expo 등)**: 코드를 일부 나눌 수 있지만 위와 같은 비용(개발자 계정, 배포)이 그대로고, 화면을 다시 만들어야 한다.
- **PWA + 웹 푸시(선택)**: 이미 Vercel에 배포하는 웹 앱 하나로 끝난다. 추가 비용이 없고 배포가 그대로다.

## Consequences

- iPhone 멤버는 Safari에서 홈 화면에 추가한 뒤 앱 안에서 알림을 켜야 한다. 추가하지 않으면 알림을 켤 수 없고, 앱은 그렇게 안내한다.
- 푸시는 브라우저(Apple·Google·Mozilla)의 푸시 서비스가 전달한다. 구독 주소가 죽으면(404/410) 서버가 그 구독을 지운다.
- 푸시 비밀 키(VAPID)가 새로 필요하다. 서버 환경 변수로만 두고 `NEXT_PUBLIC_`은 쓰지 않는다.
- 나중에 네이티브 앱이 필요해지면 푸시 대상 계산(`planPushes`)은 그대로 쓰고 발송 모듈만 바꾼다.
