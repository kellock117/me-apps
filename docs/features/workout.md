# 운동 앱 (`apps/workout`)

세트 타이머 겸 운동 기록장입니다. 노션 아티팩트로 쓰던 프로토타입을 정식 웹앱으로 옮겼습니다. 게스트에게는 근육 지도와 도움말만 보입니다([게스트 모드](guest-mode.md)).

## 무엇
- 부위(하체/상체)를 골라 시작하면 지난 기록의 세트·횟수가 자동으로 채워집니다. 세트 체크, 휴식 타이머, 순서 잠금이 있고, 운동을 끝내면 검토 후 저장합니다.
- 근육 지도(앞·뒤), 운동 가이드 시트, 건너뛰기 → 되돌리기 토스트가 있습니다.

## 어떻게 동작하나
- 테이블: `workout_sessions`(id는 화면이 만든 `s_<시각>`, part는 `lower`/`upper`, date, 시작·끝 시각, memo), `workout_sets`(기본 키 `(session_id, ord, set_no)` 복합 키, 자동 id 없음), `workout_drafts`(`id='current'`, 진행 중 임시 저장, 백업 제외). 휴식·합계는 저장하지 않고 계산합니다.
- 구분 값은 DB·코드 모두 `lower`/`upper`입니다(아티팩트의 `l`/`u`는 쓰지 않습니다).
- 날짜·시각 표시는 서울(UTC+9) 고정입니다. 폰 시간대가 달라도, 서버(UTC)에서 계산해도 같은 값이 나옵니다. 새벽 5시 전 시작은 전날로 셉니다(`lib/calc.ts`의 `workoutDate`, 테스트로 고정).
- 저장(`finishWorkout`)은 세션 id로 upsert + 세트를 지웠다 다시 넣는 방식이라 여러 번 눌러도 결과가 같습니다. 날짜는 클라이언트 값이 아니라 서버가 시작 시각에서 계산합니다.
- 임시 저장은 기기(localStorage)에 즉시, 서버(`workout_drafts`)에 디바운스로 씁니다. 두 곳 중 `ts`가 더 새로운 쪽을 따릅니다.
- `workout_sets`의 복합 기본 키 덕분에 같은 세트를 다시 저장해도 겹치지 않고, 백업 복원 때 id 충돌·시퀀스 문제도 없습니다. 백업 표의 conflictKey도 같습니다.

## 특이사항
- 아티팩트에 있던 "데드버그 / 플랭크(초)" 종목은 11/09에 루틴에서 뺐습니다. 단위 '초'는 종목 데이터의 `unit`으로 남겨 두었습니다.
- 근육 지도 SVG 경로(`lib/body-paths.ts`)는 아티팩트에서 스크립트로 옮긴 값입니다(앞 26·뒤 20·공통 8개 일치 확인). 손으로 고치지 않습니다.
- 이 앱의 `--outline`(근육 윤곽선)은 공용 테마의 `--ink`(글자색)와 이름이 겹쳐서 분리했습니다. 공용 `--ink`는 `--fg`를 가리킵니다.
- 첫 기록 이전: `pnpm --filter workout import:1109`(멱등).
- **개인 정보**: `apps/workout/components/help-sheet.tsx`에 사용자의 신체 수치가 들어 있습니다. 이 레포는 공개이므로 그 문단은 빼야 합니다. 운동 가이드의 채팅 투 마지막 문장("지금 가지고 계신 장비가…")은 앱에서 뺐습니다.
- **미검증**: 실제 iPhone(Safari)에서 화면 잠금·백그라운드 후 타이머, 1:30 삑 소리, 시간·횟수 입력(`TimeInput`, `RepsInput`)의 실기기 동작. 로직은 `calc.test.ts`로 고정했지만 화면 입력은 브라우저에서 눌러 보지 않았습니다(TODO에 올렸습니다).
