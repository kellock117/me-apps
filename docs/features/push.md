# 푸시 알림 (알림 켜기와 테스트 푸시)

앱을 열지 않아도 휴대폰에 알림이 오게 하는 기능입니다. 스펙은 #53, 이 문서는 #56(알림 켜기·테스트 푸시), #57(주차 알림·크론), #58(모임 당일 알림), #64(첫 접속 안내)를 담습니다. 새 모임·날짜 변경 알림은 이후 티켓에서 이어 적습니다. 왜 네이티브 앱이 아니라 웹 푸시인지는 [ADR 0004](../adr/0004-pwa-web-push.md).

## 무엇
- **알림 켜기**: 🔔 드롭다운 맨 아래 한 줄. 상태는 다섯 가지입니다.
  - 지원 안 함: "이 브라우저는 알림을 받을 수 없어요"
  - iOS인데 홈 화면 앱이 아님: "홈 화면에 추가하면 알림을 켤 수 있어요" + [방법 보기](설치 안내를 다시 엶)
  - 권한 거절: "알림이 꺼져 있어요. iPhone 설정 → 알림 → 이 앱에서 켜 주세요"(🔔로는 못 켜서 설정 위치를 말함)
  - 꺼짐: [이 기기에서 알림 켜기]
  - 켜짐: "이 기기에서 알림을 받아요" + [끄기]
- 게스트에게는 🔔가 없어서 줄도 없습니다. 서버에 VAPID 키가 없으면(로컬 등) 줄이 아예 안 나옵니다.
- **첫 접속 안내**(#64): 로그인한 멤버가 들어오면 이 기기 상태에 맞는 안내를 **하나만** 모달로 띄웁니다. iPhone 전용(Android 안내 없음), 게스트에게는 없습니다.
  - 홈 화면에 추가 전 → **설치 안내**: 맨 위에 "왜 추가하나요"(iPhone은 홈 화면 앱에서만 알림을 받음), 아래에 3단계(공유 → 홈 화면에 추가 → 추가) 그림. iOS에는 설치 API가 없고, 공유 시트를 `navigator.share()`로 열면 "홈 화면에 추가"가 안 보여서 버튼은 두지 않습니다(직접 Safari 공유 버튼을 눌러야 함).
  - 추가 후 + 알림 아직 안 켬 → **알림 안내창**: 왜 켜야 하는지와 [알림 켜기] / [아니요]. [알림 켜기]를 누른 동작 안에서 시스템 허용 창을 띄웁니다. [아니요]는 시스템 창을 쓰지 않고, "🔔 맨 아래에서 언제든 켤 수 있어요"라고 알린 뒤 닫습니다(시스템 창을 안 썼으니 🔔로 켤 수 있음). 시스템 창에서 "허용 안 함"을 누르면 🔔로는 못 켜므로 iPhone 설정으로 가라고 안내합니다.
  - 켬·거절·지원 안 함이면 없습니다. 안내를 닫거나 "아니요"를 하면 이 기기(localStorage `book:guide:install-dismissed`, `book:guide:ask-dismissed`)에 적고 다시 자동으로 띄우지 않습니다(기기마다 한 번씩). **개발 서버(`next dev`)에서는** 닫은 기록을 무시하고 항상 띄웁니다. 관리 화면 맨 아래 체크박스(`book:guide:dev-always`)로 끌 수 있고, 운영 빌드에는 없습니다. 결정은 순수 함수 `decideGuide`(`lib/push/guide.ts`), 화면은 `components/first-run-guide.tsx`.
  - 설치 안내 그림은 `public/guide/install-1~3.svg`(설명용 그림). 실제 iPhone 화면 사진으로 바꾸려면 같은 이름의 파일(확장자 포함 `INSTALL_STEPS` 경로)로 교체합니다. 사진은 공개 레포이므로 개인 정보가 없는 화면만.
- **주차 알림**(#57): 각 주차의 마지막 날 18시(KST)에 옵니다. 모임이 있는 주차는 모임 전날입니다(주차 마감일과 모임 전날이 이틀 연속이면 둘 다 옵니다). 알림을 켠 활동 멤버 모두에게 가고, 한 멤버에게 하나만 갑니다.
  - 제목: `📚 모임까지 D-14 · 12월 13일(일)`, 모임 전날은 `📚 내일 모임이에요 (D-1) · 12월 13일(일)`.
  - 본문(할 일 알림 `pendingNotices` 계산을 그대로 씀, 읽음으로 숨긴 진도는 뺌): 할 일 없음 "진도·별점 다 적었어요. 이번 주도 함께 읽어요" / 진도 "『책』 2주차 진도를 아직 안 적었어요" / 별점 "『책』 별점을 아직 안 남겼어요" / 별점 2권 이상 "『책』 외 1권 별점을 …" / 둘 다 "『책』 2주차 진도와 『책』 별점을 아직 안 남겼어요".
  - 누르면: 할 일 0개 → 홈(모달 없음), 진도 1개 → 그 책 상세, 별점 1개 → 그 책 평점 화면, 2개 이상 → 홈(`/?todo=1`)에서 할 일 모달이 **오늘 이미 닫았어도** 뜹니다(하루 한 번 규칙을 넘김).
  - 다음 모임이 없거나 첫 책(앞 모임 없음)이면 오지 않습니다. 모임 날짜가 바뀌면 다음 크론부터 바뀐 일정으로 계산합니다.
- **모임 당일 알림**(#58): 모임 날 18시(KST) 크론에서 주차 알림과 같이 계산합니다(`planMeetingDay`). 알림을 켠 활동 멤버 모두에게 단독으로 가고, 제목은 `📚 오늘 모임이에요 · 12월 13일(일)`(시각 없음).
  - 완독 전: "『책』 오늘 만나요. 마지막으로 얼마나 읽었는지 적어 주세요", 누르면 책 상세. 완독(그 책 마지막 기록의 쪽수 = 총 쪽수): "오늘 만나요", 누르면 모임 목록(`/meetings`, 모임 상세 화면은 따로 없음). 기록이 없거나 총 쪽수를 모르면 완독 전으로 봅니다.
  - 보낸 기록 키 `meetingday:<모임 id>:<날짜>`(주차 키와 달라서 서로 막지 않음).
- **테스트 푸시**: 관리 화면 "푸시 알림"에서 케이스(연결 확인 / 주차: 할 일 없음·진도·별점·별점 2권 이상·둘 다·D-1 / 모임 당일: 완독 전·완독)를 골라 [나에게 테스트 푸시 보내기]. 지금 로그인한 관리자 본인의 기기에만 가고 제목 앞에 `[테스트]`가 붙습니다. 실제 DB의 다음 모임·읽는 책·읽은 책으로 만들고 할 일 모양만 고른 케이스로 채웁니다(보내는 날·보낸 기록·숨김은 보지 않음). 보낸 기록에 남기지 않습니다. 데이터가 모자라면(다음 모임·읽는 책·읽은 책 없음) 이유를 알려 줍니다. 모임 당일 케이스는 다음 모임(오늘 모임이 있으면 그 모임)의 책으로 만들고 제목 날짜는 오늘로 씁니다. 로컬은 `pnpm --filter book seed:dev`가 모든 케이스를 볼 수 있는 데이터를 넣습니다(다음 모임·책이 이미 들어 있어 모임 당일 케이스도 추가 데이터 없이 됩니다).

## 동작
- **구독 저장** `book_push_subscriptions`(멤버, 구독 주소, p256dh, auth, 만든 시각; (멤버, 구독 주소)가 기본 키, 멤버를 지우면 함께 삭제). 서버 액션 `savePushSubscription`, `removePushSubscription`(`app/(main)/push-actions.ts`)이 첫 줄에서 `getCurrentMember()`로 로그인을 확인하고 zod(`lib/validation/push.ts`)로 모양을 검사합니다. 저장은 upsert, 삭제는 지금 멤버의 그 구독만 지웁니다.
- **켜짐 판정**: 이 기기의 브라우저 구독이 있고, 그 주소가 **지금 멤버 이름으로** 저장되어 있을 때만 켜짐입니다(레이아웃이 지금 멤버의 주소 목록을 넘김).
- **권한 요청**은 [켜기]를 누른 순간에만 합니다(iOS는 사용자 동작 안에서만 허용).
- **VAPID 키**: 공개 키는 `NEXT_PUBLIC_` 없이 서버(레이아웃)가 `VAPID_PUBLIC_KEY`를 읽어 props로 넘깁니다. 비밀 키(`VAPID_PRIVATE_KEY`)와 연락처(`VAPID_SUBJECT`)는 서버 환경 변수에만 둡니다. 키는 `npx web-push generate-vapid-keys`로 만듭니다.
- **발송**(`lib/push/send.ts`, `web-push`): 한 멤버의 모든 기기에 보냅니다. 푸시 서비스가 404/410을 답하면 그 구독을 지우고, 다른 실패는 로그만 남기고 던지지 않습니다(알림 때문에 모임 저장 같은 호출한 쪽 작업이 실패하면 안 되므로).
- **대상 계산**(`lib/push/plan.ts`, 순수 함수 `planPushes`): 입력(오늘 서울 날짜, 모임·책, 멤버, 진도·평점, 숨김 키, 보낸 기록, 종류) → 출력(멤버, 보낸 기록 키, 제목, 본문, 이동 주소). 주차 일정은 `weekSchedule`, 할 일은 `pendingNotices`를 씁니다. 크론·관리자 화면은 데이터를 모아(`lib/push/data.ts`) 이 함수를 부르고, 결과를 보내고 기록만 합니다(`lib/push/deliver.ts`). 나중에 네이티브 앱이 필요해져도 이 계산은 그대로 쓰고 발송 모듈만 바꿉니다.
- **보낸 기록** `book_push_sent`(멤버, 키, 보낸 시각; (멤버, 키)가 기본 키). 키 `weekly:<모임 id>:<날짜>`. 같은 키가 있으면 보내지 않고, **발송이 성공한 뒤에만**(기기에 하나라도 갔을 때) 남깁니다. 그래서 크론을 같은 날 다시 불러도 같은 알림이 두 번 가지 않고, 기기가 없거나 모두 실패한 멤버는 다시 불러 보낼 수 있습니다.
- **크론** `/api/cron/progress-push`(`apps/book/vercel.json`, `0 9 * * *` = 18시 KST). `CRON_SECRET` Bearer가 아니면 401. 돌 때마다 DB의 모임으로 오늘 보낼 것을 다시 계산하고, 응답은 `{ ok, today, planned, sent, removed, failed }`입니다. 데이터를 못 읽으면 500(조용히 "보낼 게 없다"로 넘기지 않음).
- **서비스 워커**(`public/sw.js`): `push`에서 `{ title, body, url }`을 알림으로 띄우고, `notificationclick`에서 같은 사이트 창이 열려 있으면 그 창을 이동시키고 없으면 새로 엽니다. 이동 주소는 `/`로 시작하는 같은 사이트 경로만 받습니다.

## 특이사항
- **Vercel Hobby 크론은 지정한 시 안의 아무 때나 실행됩니다.** 18:00~18:59 사이에 도착하고 정각을 보장하지 않습니다. 날짜는 실행 시각의 서울 날짜로 정합니다.
- **보낸 기록 표는 계속 쌓입니다**(멤버 × 날). 멤버 몇 명 규모라 지우지 않습니다.
- **iPhone**: iOS 16.4 이상에서 **홈 화면에 추가한 앱**에서만 푸시를 받습니다. Safari 탭에서는 푸시 API 자체가 없어서 "홈 화면에 추가" 안내가 먼저 나옵니다.
- **같은 기기에서 멤버를 바꿔 쓰면** 그 멤버 구독이 따로 생기고, 그 기기에는 두 멤버의 알림이 모두 옵니다(앞 멤버 구독을 자동으로 정리하지 않음. 범위 밖).
- **안내창이 다른 모달(할 일 등) 아래에 깔리지 않게** 열린 직후 다른 모달이 있으면 닫았다 다시 엽니다(`close` 이벤트는 비동기라 `onClose`에서 다시 열려 있는지로 거릅니다).
- **포커스 링은 앱 전체에서 없앱니다**(`theme.css`의 `:focus-visible { outline: none }`, workout도 포함). 모달을 열면 제목에 프로그램으로 포커스를 주는데 iOS가 노란 링을 그려서입니다. 페이지 이동 중에는 `(main)/loading.tsx`의 상단 막대가 뜹니다.
- **끄기는 서버 저장만 지웁니다.** 브라우저 구독은 풀지 않습니다. 같은 기기의 다른 멤버가 같은 구독을 쓰고 있을 수 있어서, 풀면 그 멤버 알림이 죽습니다.
- 구독 주소와 키는 비밀로 다룹니다. 화면에는 지금 멤버 본인 주소만 켜짐 비교용으로 넘기고, 백업에는 넣지 않습니다([백업](backup.md)).
- 새 멤버·기기가 늘면 표가 커지지만 멤버 몇 명 규모라 문제 없습니다.
