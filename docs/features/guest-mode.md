# 읽기 전용 공개(게스트 모드)

로그인하지 않은 사람(게스트)에게는 읽는 화면만 열어 주는 기능입니다. 스위치(환경 변수)는 없고 항상 이렇게 동작합니다.

## 무엇
- 로그인은 화면 우측 상단 "로그인" 버튼(`@me/ui/guest-login`) → 따로 있는 `/login` 화면에서 비밀번호만 치면 됩니다. 맞으면 보던 화면으로 돌아옵니다(`?next=`).
- 게스트가 볼 수 있는 것: 책 상세의 리뷰·인상 깊은 문장과 문장 탭(`/quotes`, #47부터; 쓴 사람 이름은 가려짐), 홈의 "모두의 진도" 그래프·속도 표(범례·표의 멤버 이름이 "멤버 A"처럼 가려짐; 진도 기록은 `getClubData()`의 `reading_progress`를 그대로 씀). 책 상세의 "내 진도"는 로그인한 멤버에게만 나옵니다. 미평점 책 모달은 안 뜹니다.
- 게스트가 못 하는 것: 평점·추천·선정·모임 수정, 책 검색 API, 관리자 화면·백업 내려받기, workout의 기록 화면(근육 지도와 도움말만 보입니다).
- 게스트에게는 멤버 실명을 가립니다("멤버 A", "멤버 B" …, `rotation_order` 순).

## 어떻게 동작하나
- **볼 수 있는 화면**은 각 앱 `proxy.ts`의 허용 목록으로 정합니다(book은 `GUEST_PAGES`, workout은 `/`만). 그 밖의 주소는 로그인으로 보냅니다. 새 읽기 화면을 만들면 거기에 넣어야 게스트에게 보입니다. 기본은 잠김입니다.
- **쓰기는 서버 액션 안에서 막습니다.** proxy의 허용 목록만으로는 부족합니다. 서버 액션은 어느 주소로든 호출될 수 있고, 게스트가 열어 둔 화면 주소로도 보낼 수 있어서입니다. 모든 쓰기 액션이 로그인을 다시 확인합니다(book은 `getCurrentMember()`가 세션 쿠키도 검사해 게스트면 null, workout은 `requireSite()`). 화면 버튼을 숨기는 것은 편의일 뿐입니다.
- **이름 가리기**는 모든 화면이 거치는 `getClubData()`에서 한 번에 합니다(`apps/book/lib/guest-mask.ts`). 자유 글(리뷰 등) 속 이름도 치환합니다.
- **workout 게스트**: 서버가 게스트에게는 DB를 아예 읽지 않습니다. 기록·지난 운동·임시 저장은 읽지 않습니다.

## 특이사항
- **스위치가 없습니다**: 처음에는 환경 변수(PUBLIC_READONLY)로 켜고 끄게 했다가, 어차피 공개할 것이라 뺐습니다. 배포하면 바로 공개됩니다. 긴급히 닫아야 하면 각 앱 `proxy.ts`의 허용 목록(`GUEST_PAGES`, workout은 `/`)을 비우고 배포합니다.
- **막은 구멍**: 예전에는 "누구" 쿠키(`club_member`, 멤버 id만 알면 만들 수 있음)만 보고 쓰기를 허용했고, 로그인 확인은 proxy에만 있었습니다. 게스트가 열리면 이 쿠키를 흉내 낼 수 있어서, `getCurrentMember()`가 세션 쿠키도 검사하고 `chooseMember`·책 검색 API도 로그인을 확인하게 했습니다.
- **proxy는 POST를 구분하지 않습니다.** 그래서 쓰기 보호의 실제 방어선은 액션 안의 확인입니다.
- **오늘의 문장 서버 액션(`getDailyQuote`)은 로그인 확인이 없는 읽기**입니다. 데이터는 `getClubData()`를 거쳐 가려집니다.
- **새 데이터 읽기 경로를 `getClubData()` 밖에 만들지 않습니다.** 만들면 이름이 샐 수 있습니다.
- **이름 가리기의 한계**: 자유 글 속 이름은 전체 이름과 성을 뗀 이름(2글자 이상일 때)을 치환합니다. 별명이나 초성은 못 잡습니다. 성 뗀 이름이 다른 낱말과 겹치면 그 낱말도 바뀝니다.
- **가려지지 않는 것**: 책 제목·저자·모임 장소·날짜, 평점 점수. 독서 규칙 페이지(`apps/book/content/rules.md`)는 DB가 아니라 파일이라 가려지지 않으므로 이 파일에는 실명을 쓰지 않습니다(선정 순서는 홈의 "다음 선정자"가 보여 줍니다).
- **`next dev`에서는 로그인이 생략됩니다**(`packages/core/src/auth/dev-login.ts`, NODE_ENV가 development일 때만). 두 앱 proxy, book `isLoggedIn`, `verifySiteToken`이 통과시키므로 쓰기 액션도 열립니다. book은 "나는 누구" 선택(/who)은 그대로 거칩니다. 관리자 화면 비밀번호는 생략하지 않습니다. 게스트 화면을 보려면 `DEV_LOGIN_SKIP=0`으로 서버를 띄웁니다. `next build`·`next start`(Vercel 운영·프리뷰 포함)는 production이라 영향이 없습니다.
- **로컬 확인 때 주의**: 브라우저는 쿠키를 포트가 아니라 호스트(localhost)로 구분해서, 이전에 로그인한 기록이 있으면 게스트 화면이 안 보입니다. `WORKOUT_PASSWORD`를 바꿔서 서버를 다시 띄우면 확인할 수 있습니다. 또 `apps/workout/.env.local`의 `SUPABASE_URL`이 운영 DB를 가리키고 있을 수 있으니, 로컬 시험은 로컬 주소로 덮어쓰고 합니다.
